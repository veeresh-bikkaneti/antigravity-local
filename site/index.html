Your coding agent, on your own machine

Local Antigravity runs the Google Antigravity SDK against a model on your computer, served by Ollama. Setup needs no cloud account and no API key.

Start the guide ▶ Play the zero-to-coding game See the code on GitHub

Version 1.0.0. Tested on Windows 11. macOS and Linux are not tested yet.

Before you start

  • Windows 11 is the only system we tested natively.
  • About 10 GB of free disk for the 14B model, and 16 GB of RAM or more for comfort.
  • Python 3.11 or newer, git, and Ollama for Windows, macOS, or Linux.
  • Time: a few minutes of setup plus the model download, which is roughly 9 GB for the 14B model.

Want a coding agent that runs on your own machine, with no API fees?

Clone the repo and run run.bat.

It checks your hardware, then picks a model that fits. Already have one? It reuses it, with no second download.

If Ollama isn't already running, it starts it for you, and sets up a virtual environment, so your Python stays tidy.

Then the agent proves itself. It writes a workspace/index.html file with its own tool calling. Small models sometimes skip the write. If so, run it again.

Finally, you land at a chat prompt. Ask for code, or ask it to read your files.

Prefer a browser? Run python run.py --serve. You get a search page and an API, on a free port.

Your code and prompts go only to a model on your own hardware. Install Ollama first if you don't have it. Then setup downloads the Python packages, and a model if you need one. Give it a few minutes.

Three things we care about

It stays here

Your code and your prompts go to a model on your own computer. Setup needs no cloud account and no API key.

It tells you when it fails

If a task writes no file, the tool says so instead of reporting success. The limits are on this page, with numbers.

It starts small

One command sets it up, or run one Docker image. Both pick a free port, so nothing fights with what you already run.

From zero to your first file

Seven steps, in order. The drawing shows where each one happens on your machine.

  1. Install Ollama

    Ollama is the program that holds the model and answers requests. Download it from ollama.com/download, then check it works.

    ollama --version

    You should see a version number. If the command is not found, open a new terminal.

    About 3 minutes

  2. Choose a model (optional)

    Step 3 picks a model that fits your machine, so you can skip this. To choose one yourself, pull the model run.py would pick: qwen2.5-coder:14b with 15 GB or more of VRAM, qwen2.5-coder:7b with 8 GB of VRAM or 16 GB of RAM, and llama3.2:3b otherwise.

    ollama pull qwen2.5-coder:7b

    You should see the model in ollama list.

    Depends on your connection

  3. Clone the repo and run setup

    One command builds a Python environment, installs the packages, and runs a short demo.

    git clone https://github.com/veeresh-bikkaneti/antigravity-local.git
cd antigravity-local
python run.py

    You should see four numbered stages and then a You > prompt. Type exit for now. On macOS and Linux, use python3. On Windows you can also run .\run.ps1 or run.bat.

    About 3 minutes the first time, not counting a model download. It goes quiet in the middle while packages install, and that is normal.

    Two common errors. No module named 'google' means you are outside the virtual environment, so activate it (step 4). Connection refused on :11434 means Ollama is not running, so start the app or run ollama serve.

  4. Activate the virtual environment

    Do this once per terminal window, from inside the antigravity-local folder.

    Windows PowerShell

    .\venv\Scripts\Activate.ps1

    macOS and Linux

    source venv/bin/activate

    Your prompt now starts with (venv). If PowerShell blocks the script, the guide has the one-line fix.

    10 seconds

  5. Chat with your agent

    Open the coding shell on a workspace folder. Type a request in plain English. Creating a new file works most of the time. Editing an existing file does not, so read the limits below before you point it at real code.

    python code_agent.py --workspace ./workspace

    A banner shows your model and workspace, then a CodeAgent [You] > prompt. Try /files, then /wiki, then exit. /clear starts a fresh session.

    1 minute

  6. Give it one job

    Hand the agent a single task and let it finish without chatting.

    python code_agent.py --workspace ./my-project --task "Create hello.py that prints hi"

    You should see Task completed. Created 1, changed 0. and the new file listed. If you see a warning instead, the model answered without writing a file. Run the command again.

    Under a minute

  7. Use it from your editor or the browser

    Start a search page on a free port, or run the Docker image. For VS Code, the README lists four routes: our shell in the terminal, the Ollama extension, Continue, and Cline.

    python run.py --serve

    You should see Serving on http://127.0.0.1: followed by a port number. Open that address. The first run builds its own virtual environment and installs packages, so it takes a few minutes. The page has no login, so keep it on your machine.

    Under a minute. Editor setup in the README

What it cannot do yet

These are measured limits from our own tests, not guesses.

  • Editing an existing file does not work reliably. With the default model, qwen2.5:14b, none of 14 attempts to edit a file, or to read one and write a new one, gave a correct result. Creating a new file from a plain prompt mostly works. Commit first and check git diff. A larger model may do better, and we have not tested one.
  • The Antigravity IDE chat panel has no documented setting for a local model. Google's local-model support covers the SDK, which this project uses. In the IDE, run our shell in its built-in terminal.
  • Only Windows 11 was tested. Native macOS and Linux, and the VS Code extension steps, are not tested yet.

Questions people ask

Do I need a GPU?

No. Small models run on a CPU, just slowly. A GPU with 16 GB of video memory runs the default model comfortably. The README has a table that matches models to hardware.

Does it send my code anywhere?

Not during inference. The agent talks to Ollama on your own machine. Setup does download packages, Ollama, and the model. Google's Antigravity IDE and its chat panel are separate products, and this project does not control them.

Why did my task create no file?

The model answered without calling its file tool. Small local models do this now and then. The tool prints a warning instead of "Task completed". Run the same command again, or name the file in your task.

Can I use it from VS Code?

Yes, four ways. The README lists them: our shell in the built-in terminal, the Ollama extension, Continue, and Cline. The extension steps come from their official guides, and we have not run them in VS Code ourselves.

Does it work on macOS or Linux?

The Docker image runs on Linux and passes its tests in CI. The native setup was tested only on Windows 11. We expect macOS and Linux to work, and we have not checked.
