Your coding agent, on your own machine

Local Antigravity runs the Google Antigravity SDK against a model on your computer, served by Ollama. Setup needs no cloud account and no API key.

Start the guide Zero to coding guide ▶ Play the zero-to-coding game See the code on GitHub

Version 1.2.4. Tested on Windows 11. macOS and Linux are not tested yet.

Before you start

  • Windows 11 is the only system we tested natively.
  • About 10 GB of free disk for the 14B model, and 16 GB of RAM or more for comfort.
  • Python 3.11, 3.12 or 3.13, git, and Ollama for Windows, macOS, or Linux. Step 1 shows how to install them.
  • Time: a few minutes of setup plus the model download, which is roughly 9 GB for the 14B model.

Want a coding agent that runs on your own machine, with no API fees?

Clone the repo and run run.bat.

It checks your hardware, then picks a model that fits. Already have one? It reuses it, with no second download.

If Ollama isn't already running, it starts it for you, and sets up a virtual environment, so your Python stays tidy.

In a real terminal, the agent then proves itself. It writes a workspace/index.html file with its own tool calling. Small models sometimes skip the write. If so, run it again.

Finally, you land at a chat prompt. Ask for code, or ask it to read your files. With --yes, piped input or CI, setup stops before the demo and prints a Ready: line instead.

Prefer a browser? Run python run.py --serve. You get a search page and an API, on a free port.

Your code and prompts go only to a model on your own hardware. Install Ollama first if you don't have it. Then setup downloads the Python packages, and a model if you need one. Give it a few minutes.

Three things we care about

It stays here

Your code and your prompts go to a model on your own computer. Setup needs no cloud account and no API key.

It tells you when it fails

If a task writes no file, the tool says so instead of reporting success. The limits are on this page, with numbers.

It starts small

One command sets it up, or run one Docker image. Both pick a free port, so nothing fights with what you already run.

From zero to your first file

Eight steps, in order. The drawing shows where each one happens on your machine.

  1. Install Python, Git and Ollama

    Open PowerShell (Start menu, type PowerShell) and run each command on this page there. First install Python 3.12 from python.org (tick "Add python.exe to PATH") and Git from git-scm.com. Then open a new PowerShell window. python --version and git --version should each print a version.

    Ollama is the program that holds the model and answers requests. Download it from ollama.com/download, then check it works.

    ollama --version

    You should see a version number. If the command is not found, open a new terminal.

    About 3 minutes

  2. Choose a model (optional)

    Step 3 picks a model that fits your machine, so you can skip this. On a normal terminal it shows a short menu where every row says Fast, Moderate or Slow (an estimate from the model's size and your memory) and Enter takes the pick for your machine; --yes skips the menu and never downloads. Not on Ollama? LM Studio, llama.cpp and vLLM work too: point LOCAL_LLM_BASE_URL at them and nothing gets downloaded. Want a model from Hugging Face? Type hf.co/user/repo:quant in the menu. To choose one yourself, pull the model run.py would pick: qwen2.5-coder:14b with 15 GB or more of VRAM (your graphics card's own memory), qwen2.5-coder:7b with 8 GB of VRAM or 16 GB of RAM, and llama3.2:3b otherwise. If you pick a Gemma model, tool calling is off, so it can chat but not edit files.

    ollama pull qwen2.5-coder:7b

    You should see the model in ollama list.

    Depends on your connection

  3. Clone the repo and run setup

    One command runs five stages: ENVIRONMENT (a private Python folder for this project, plus the packages), SERVER (checks Ollama), MODEL (one numbered list, where Enter keeps your model and a typo just asks again), CONTEXT (says the window your model really runs with, and the largest window this GPU can hold on top of the weights) and LAUNCH. Then a LEVEL CLEAR box sums up the model, the agent and the log file. A better model that fits shows up as a recommended upgrade row in the same numbered list, and your current model is marked with a *. If no model is installed, it asks before it downloads one (about 9 GB for the 14B model).

    git clone https://github.com/veeresh-bikkaneti/antigravity-local.git
cd antigravity-local
python run.py

    You should see five stages (STAGE 1/5 to 5/5), a LEVEL CLEAR box, and then a You > prompt. Type exit for now. On macOS and Linux, use python3. On Windows you can also run .\run.ps1 or run.bat.

    About 3 minutes the first time, not counting a model download. It goes quiet in the middle while packages install, and that is normal.

    Prefer to do it by hand? Manual setup. Script blocked on Windows? See Set-ExecutionPolicy.

    A common error: Connection refused on :11434 means Ollama is not running, so start the app or run ollama serve.

  4. Use your model in a coding app

    Your pick is saved as LOCAL_LLM_MODEL in .env, so every app uses the same model. Pick one agent below. Each command adds only an Ollama entry to that app's config, and it asks before it installs anything. Coding apps want a 64k context window. If stage 4 says yours is smaller, set OLLAMA_CONTEXT_LENGTH=65536 and restart Ollama.

    Built-in shell

    Our own pair-programmer shell. Nothing extra to install.

    python code_agent.py --workspace .

    pi

    A minimal agent with four tools and a short system prompt. Best for small local models, because there is less prompt to get lost in.

    python run.py --agent pi

    opencode

    A fuller agent with MCP, LSP and sub-agents. More features, and a better fit for bigger models.

    python run.py --agent opencode

    codex

    OpenAI's terminal agent, pointed at Ollama with --oss. Zero config files to manage.

    python run.py --agent codex

    claude

    Claude Code, pointed at your local model for one session. Run the read-only settings check first if you already use Claude Code.

    python run.py --agent claude
    python run.py --agent claude --doctor

    The app opens in your project, already pointed at your local model. Your other settings are left alone. The Claude Code route, including context-size settings and shell wrappers, is in the full guide.

    A minute, plus the app install if you say yes. Full details in the full guide

    Connect your coding app

    • VS Code: install the Ollama extension (Ollama.ollama), then pick your model under Ollama in Chat.
    • Continue: set provider: ollama, your model tag and apiBase: http://localhost:11434 in config.yaml.
    • Terminal agents: python run.py --agent pi, or opencode, codex, or claude (see the claude card above).
    • Antigravity: no documented local-model setting in the app. Run the terminal line in its built-in terminal.
    • Gemini CLI: no local models. Only a LiteLLM proxy gets there, and that is experimental and untested by us.
    • Your own code: base URL http://localhost:11434/v1 and your model tag. Steps for every app are in the Coding apps section below.

    Short version any time: python run.py --coding-apps.

  5. Activate the virtual environment

    Do this once per terminal window, from inside the antigravity-local folder.

    Windows PowerShell

    .\venv\Scripts\Activate.ps1

    macOS and Linux

    source venv/bin/activate

    Your prompt now starts with (venv). If PowerShell blocks the script, the guide has the one-line fix.

    10 seconds

    Activation blocked by PowerShell? Set-ExecutionPolicy fix.

  6. Chat with your agent

    Open the coding shell on a workspace folder. Type a request in plain English. Creating a new file works most of the time. Editing an existing file does not, so read the limits below before you point it at real code.

    python code_agent.py --workspace ./workspace

    A banner shows your model and workspace, then a CodeAgent [You] > prompt. Try /files, then /wiki, then exit. /clear starts a fresh session.

    If you see No module named 'google', you are outside the virtual environment, so activate it (step 5) and try again.

    1 minute

    Odd characters crash it on Windows? UnicodeEncodeError fix. Want to check the pieces one by one? Test scripts.

  7. Give it one job

    Hand the agent a single task and let it finish without chatting.

    python code_agent.py --workspace ./my-project --task "Create hello.py that prints hi"

    You should see Task completed. Created 1, changed 0. and the new file listed. If you see a warning instead, the model answered without writing a file. Run the command again.

    Under a minute

    Want a search UI and API instead? Serve it, local or Docker.

  8. Use it from your editor or the browser

    Start a search page on a free port, or run it in Docker (the full guide has the three Docker commands). For VS Code there are four routes:

    • Our shell in the built-in terminal. Open Terminal, then New Terminal, activate the venv and run python code_agent.py --workspace .. No extension needed.
    • The Ollama extension (Ollama.ollama). Pick your model under Ollama in Chat. Steps
    • Continue. Add your model to its config.yaml. Steps
    • Cline. The full guide has the steps. We did not re-check them on 2026-11-18.

    Want a sturdier terminal agent? python run.py --agent pi (or opencode, or codex) sets one up for your local model and asks before it installs anything. Steps

    python run.py --serve

    You should see Serving on http://127.0.0.1: followed by a port number. Open that address. A port is just a numbered door on your computer, and this command picks one that is free. The page has no login, so keep it on your machine.

    Under a minute. Full details in the full guide

    Using LM Studio or vLLM? Other backends. Done for the day? Stop and clean up.

Want something to build now? The Zero to coding guide walks through 3 end-to-end coding recipes: a FastAPI backend, unit tests for existing code, and a legacy-code refactor.

Connect your coding app

Ollama holds the model, and every app below knocks on its door at http://localhost:11434. Apps that speak the OpenAI style use http://localhost:11434/v1. Start Ollama first, and check your model with ollama list. Checked 2026-11-18. Confidence tags: High means three or more primary sources agree, Moderate means two sources or one primary source, Low means secondary or conflicting.

Coding tools want a 64k context window, and Ollama's default is 4k on a PC with under 24 GB of VRAM. Run the line for your shell (PowerShell on Windows, bash on macOS and Linux), or use the context slider in the Ollama app, then check with ollama ps. Source: Ollama's context length docs [Moderate].

$env:OLLAMA_CONTEXT_LENGTH=65536; ollama serve
OLLAMA_CONTEXT_LENGTH=65536 ollama serve
VS Code: use the Ollama extension

VS Code's built-in Ollama provider is deprecated. Use the official Ollama extension instead.

When you run python run.py --agent ..., stage 4 asks once whether to add a VS Code Chat model entry with the real context window. Nothing is written unless you answer y, and an existing file is backed up first.

The same stage 4 step can also offer a shared checkpoint file, .agl/checkpoint.md, that your coding app reads first and updates before it stops, and nothing is written unless you answer y.

Got a task too big for the window? Type /steps <task> in the built-in shell. You get a plan of 2 to 8 steps, and each step runs in a fresh chat. Quit whenever you like, and the next start offers to resume. An optional test command must exit 0 before a step counts as done.

  1. Update VS Code (1.127 or newer) and Ollama (0.17.6 or newer recommended).
  2. Install the extension with the ID Ollama.ollama.
  3. Open Chat, open the model picker, and choose your model under Ollama.
  4. If the model is missing, run Ollama: Refresh Models from the command palette. Ollama: Diagnose Models says what it sees.

Local models work without a GitHub sign-in or a Copilot plan. Completions and semantic search still need GitHub. Agent mode hides any model that does not support tool calling, so pick one with the tools badge.

Sources: VS Code language models docs, Ollama VS Code guide, GitHub changelog 2026-04-22 [Moderate]. Checked 2026-11-18.

Continue: edit config.yaml
  1. Install Continue and open its settings.
  2. Open config.yaml from there.
  3. Add your model. The model value must match ollama list exactly.
  4. Pick the model in Continue's chat box.
models:
  - name: My local model
    provider: ollama
    model: qwen2.5:14b
    apiBase: http://localhost:11434
    roles: [chat, edit]
    capabilities: [tool_use]   # needed for agent mode

Source: Continue's Ollama guide [Moderate, one primary source, written for Continue 1.1.x]. Checked 2026-11-18.

Terminal agents: one command
  1. Run python run.py --agent pi from your project. Swap pi for opencode, codex or claude.
  2. Say y if it offers to install the agent. It adds only an Ollama entry to that agent's own config.
  3. Prefer Ollama's own helper? ollama launch pi does a similar job.

Sources: this repo's agent_setup.py (covered by the offline tests) and Ollama's pi guide [Moderate]. The full guide's ollama launch app list was checked on 2026-11-14 and not re-checked. Checked 2026-11-18.

Antigravity app: no documented setting

The Antigravity app and its agent window have no documented setting for a local model. The plans page says it has no support for "Bring-your-own-key (BYOK) or bring-your-own-endpoint for additional rate limits". That wording is about rate limits, so read it as "no documented setting", not "impossible". Google's local-model page covers the SDK only.

  1. Open the app's built-in terminal in your project.
  2. Run python <path>\antigravity-local\run.py --agent pi, using the full path to where you cloned this repo.

For your own SDK code, LocalOpenAIAgentConfig(model="<tag>", base_url="http://localhost:11434/v1") is the local option, and LiteRTAgentConfig is the other. This repo's code uses the first one.

Sources: Antigravity plans page and SDK local-models page [Moderate]. Checked 2026-11-18.

Gemini CLI: proxy only, experimental

Gemini CLI has no native local-model support. A feature request (#24166, 2026-03-29) has no maintainer reply, and #23385 was closed as a possible duplicate [Moderate]. The only route we know is a LiteLLM proxy. It is experimental and not tested by us.

  1. Run a LiteLLM proxy in front of Ollama, with a model_group_alias that maps the Gemini model name to your Ollama model.
  2. Set GOOGLE_GEMINI_BASE_URL=http://localhost:4000.
  3. Set GEMINI_API_KEY to your LiteLLM key.

One report says the CLI ignores GOOGLE_GEMINI_BASE_URL when cached Google credentials exist (#15430) [Low]. Source for the route: the LiteLLM Gemini CLI tutorial [Moderate]. Checked 2026-11-18.

Your own code: any OpenAI client
  1. Set the base URL to http://localhost:11434/v1.
  2. Set the model to your tag, for example qwen2.5:14b.
  3. Use any non-empty string as the API key. Ollama ignores it.

Sources: Antigravity SDK local-models page, Ollama pi guide, Ollama VS Code guide [High]. Checked 2026-11-18.

What it cannot do yet

These are measured limits from our own tests, not guesses.

  • Editing an existing file does not work reliably. With the default model, qwen2.5:14b, none of 14 attempts to edit a file, or to read one and write a new one, gave a correct result. Creating a new file from a plain prompt mostly works. Commit first and check git diff. A larger model may do better, and we have not tested one.
  • The Antigravity app and its IDE chat panel have no setting for a local model, and Google's plans page says bring-your-own-endpoint is not supported. Google's local-model support covers the SDK, which this project uses. In the IDE's built-in terminal, run python <path-to>/antigravity-local/run.py --agent pi from your project, or use our shell. The Antigravity and Gemini command-line tools can reach a local model only through a translating proxy. That route is experimental and we have not tested it.
  • The extra coding agents (pi, OpenCode, Codex) are set up and tested offline. We have not yet measured how well they edit an existing file with your model, and all three want a context window of 64k tokens or more, which is larger than Ollama's default on most PCs.
  • Only Windows 11 was tested. Native macOS and Linux, and the VS Code extension steps, are not tested yet. VS Code's built-in Ollama provider is deprecated, so the steps use the Ollama extension.

Questions people ask

Do I need a GPU?

No. Small models run on a CPU, just slowly. A GPU with 16 GB of video memory runs the default model comfortably. The full guide has a table that matches models to hardware.

Does it send my code anywhere?

Not during inference. The agent talks to Ollama on your own machine. Setup does download packages, Ollama, and the model. Google's Antigravity IDE and its chat panel are separate products, and this project does not control them.

Why did my task create no file?

The model answered without calling its file tool. Small local models do this now and then. The tool prints a warning instead of "Task completed". Run the same command again, or name the file in your task.

Something broke. Where do I look?

The troubleshooting section of the full guide lists the common ones, starting with the PowerShell "Running scripts is disabled" error.

Do I need a 24 GB graphics card?

No. This project targets 8 to 16 GB machines and CPU-only laptops. It goes through Ollama and the SDK's LocalOpenAIAgentConfig route. The other local route, litert-lm, needs 24 GB or more of VRAM for models over 16 GB, and it fails on 16 GB laptop cards (see the project's hardware matrix).

Can I use it from VS Code?

Yes, four ways. The full guide lists them: our shell in the built-in terminal, the Ollama extension, Continue, and Cline. VS Code's built-in Ollama provider is deprecated, so use the official Ollama extension (Ollama.ollama). The extension steps come from their official guides, and we have not run them in VS Code ourselves. Steps for each app

Can I use a better coding agent than the built-in shell?

Yes. Run python run.py --agent pi, --agent opencode or --agent codex. It adds an Ollama entry to that agent's own config, keeps everything else in the file, makes a one-time backup, and starts the agent in your project folder: the folder you ran it from, or whatever you pass to --workspace. Run it from inside antigravity-local and it uses this repo's workspace/ folder instead, so it never edits our own files by accident. It installs the agent only if you type y. Raise Ollama's context length to 64k first, for example with OLLAMA_CONTEXT_LENGTH=65536.

Can I use Claude Code with my local model?

Yes, with one command: python run.py --agent claude. Ollama speaks a subset of the Anthropic API, and we hand Claude Code the endpoint, a placeholder token and your local model for that one session only. It gets its own config folder (~/.claude-local) and we never write your ~/.claude settings, so your normal sessions stay on your subscription. python run.py --agent claude --doctor checks, read-only, that nothing else is rerouting them. The offline tests pass, but we have not yet run a long live session. The full guide has the details and the gotchas.

Does it work on macOS or Linux?

The Docker image runs on Linux and passes its tests in CI. The native setup was tested only on Windows 11. We expect macOS and Linux to work, and we have not checked.
